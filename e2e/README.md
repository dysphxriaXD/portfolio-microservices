# E2E-тесты

Модуль `e2e` отдельный и от сервисов не зависит. Тесты проверяют систему
целиком: поднимают `inventory`, `payment` и `order` как реальные Docker-контейнеры
через [testcontainers-go](https://golang.testcontainers.org/) и общаются с ними
по настоящему gRPC/HTTP, не импортируя внутренний код сервисов.

## Запуск

Нужен запущенный Docker:

```bash
task test:e2e      # из корня проекта (на неделе 1 task test — алиас на test:e2e)
# или
go test -p 1 -count=1 ./e2e/...
```

`-p 1` гоняет пакеты последовательно: inventory/payment и order-стек собирают
одни и те же образы сервисов, при параллельном прогоне это даёт гонку сборки в
Docker. Первый прогон дольше: собираются образы сервисов. Повторные быстрее за
счёт кэша Docker.

## Откуда берутся образы

Из единого `deploy/docker/Dockerfile` (нужный сервис выбирается
build-аргументом `SERVICE`). Контекстом сборки служит корень проекта.
Подробно контейнеризацию и Dockerfile'ы разбираем на неделе 8, а пока на них можно
не отвлекаться.
